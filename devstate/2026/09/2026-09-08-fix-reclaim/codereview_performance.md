# Performance

1. [hard] Unbounded concurrency — `pkg/reclaim/table.go:215` — the new `arming` window lets a slot end with zero holders, no armed timer, and no way to reach `fire`, so its refresh ticker never stops and its `t.items` entry is never evicted. Interleaving: `drop` A empties the holders, sets `e.arming = true`, unlocks and enters `orphanLog.Debug`; an `Open` binds in that window (`bindLocked` sees `arming`, bumps `graceGen`, adds a holder); that holder's ctx is already Done so its `watch` calls `drop` B, which finds `len(e.holders) == 0` but returns early on `e.arming` (line 215) without arming grace; `drop` A then reacquires and returns on `e.graceGen != gen` (line 232). Before this diff `drop` armed the timer under the same acquisition that emptied `holders`, so this state was unreachable. The stranded slot keeps the `*BIN` / `*MMDB` wrapper alive — its download ticker keeps firing and its database file stays open — until the same key is opened again; on a hash change that key never returns, so one leaked ticker plus one retained database accumulates per stranded old hash, and reload frequency is the growth source (`drop` runs on every holder ctx completion, `Open` on every plugin construction). No TTL or sweeper sits in between: eviction happens only in `fire`.
   → In the re-lock block, when `t.items[key] == e` and `len(e.holders) == 0`, arm grace against the current `e.graceGen` instead of returning on the generation mismatch.
   Status: done
   Argument: Applied as written: `drop`'s second critical section now returns only when the slot is unmapped or has holders, and arms against the generation it reads at that moment. Added `TestTable_ReclaimAndReleaseInsideOrphanWindowStillArms`, which drives the exact interleaving with a log handler that blocks on the orphan line, then asserts the value was closed and the key evicted. Against the pre-fix `drop` it times out on all 3 runs (the slot is stranded); post-fix it passes in 0.01 s. `design.md` and `explore.md` now carry the reasoning.

3. [judgement] Unnecessary test wall clock — `pkg/dbwrappers/reclaim_test.go:148` — `time.Sleep(50 * time.Millisecond)` no longer straddles anything now that this test uses `graceReclaimSafe = 5 * time.Second`: the grace edge is 100x away, so the sleep buys no signal the lookup on the next line does not already give. Same at `pkg/dbwrappers/reclaim_test.go:269`. Measured 0.05 s and 0.06 s for two tests whose remaining work is otherwise sub-millisecond.
   → Drop both sleeps and keep the lookup assertion.
   Status: skipped
   Argument: Measured wrong. Dropping both sleeps failed 5 of 25 stressed runs with `TempDir RemoveAll cleanup: directory not empty`. They were not straddling the grace edge — they were covering a gap in `pkg/dbsource`: `Updater.Start` runs the first tick on a new goroutine, `tick` never checks for stop before downloading, and `Updater.Stop` only closes a channel, so a disposed wrapper can still write into its directory and race the RemoveAll that `t.TempDir` registers. Extending the grace to 5 s widened that window by keeping the wrapper alive to the end of the test. Two attempts to make it deterministic failed: an explicit `Reset()` before teardown is not enough because `Stop` does not wait, and waiting for `Updater.Latest()` never completes because that download is what fails. So the wait stays, now named `settleFirstTick` with the cause in its doc comment, plus `releaseLeases` for a deterministic close. The real fix is to cancel the in-flight request in `pkg/dbsource` and wait for the goroutine — recorded as a card follow-up, out of scope for a reclaim ticket.
