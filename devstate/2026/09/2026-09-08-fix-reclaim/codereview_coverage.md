# Test coverage

Ticket job (requirement.md Problem + proposal Why): `reclaim_dispose` must mean the stored value's `Close()` has returned, `reclaim_orphan` must always precede it, and the reclaim tests must stop requiring a 3 ms timer to lose. That job is proven: `TestTable_DisposeLogFollowsClose` / `TestTable_ResetDisposeLogFollowsClose` (`pkg/reclaim/table_test.go:956`, `:976`) read the dispose count from inside `Close()`, and `TestTable_OrphanPrecedesDisposeAtTinyGrace` (`:1000`) pins the sequence at a 1 ns grace — all three fail against `origin/master`'s `table.go`. Findings below are the remaining holes.

1. [hard] Edge case untested — `pkg/reclaim/table.go:232` — the `arming` window is the new state this change added, and the skip-the-arm branch in `drop` (`t.items[key] != e || e.graceGen != gen`) has no test that enters it through `drop`. Measured with `-covermode=count` on the full suite: that branch is taken 8 times, all incidental inside stress loops, with no assertion attached; `bindLocked`'s arming-only arm is taken 4 times, 1 of which is the white-box test. `TestTable_BindWhileArmingReclaims` (`pkg/reclaim/table_test.go:1020`) sets `e.arming = true` by hand and calls `bindLocked` directly, so it never runs `drop`, never observes that the timer stayed unarmed, and never records a log line — its own comment ("stops that arming from happening") is unasserted, and the spec order `reclaim_orphan` then `reclaim_reclaim` for an `Open` that lands in that window is unasserted anywhere at any grace.
   → Enter the window deterministically through the existing seam: a `slog.Handler` that blocks inside `Handle` on `MsgOrphan` while a second `Open` binds, then assert under `tab.mu` that the slot is still mapped with `graceTimer == nil`, that `keySeq` is put, bind, orphan, reclaim, bind, and that no dispose was logged.
   Status: done
   Argument: Applied through the seam suggested. `TestTable_OpenInsideOrphanWindowKeepsIncarnationLive` gates the orphan line, binds a live holder inside the window, waits for `arming` to clear (the point where `drop` decides), then asserts the slot is still mapped, `graceTimer == nil`, one holder, the value not closed after 20 grace periods, and no dispose. It does assert the put/bind/orphan/reclaim/bind sequence, with a comment that the gate is what pins that order here - the spec deliberately does not guarantee it, since the bind takes the mutex `drop` released in order to log.
2. [hard] Critical path untested — `pkg/reclaim/table_test.go:831` — the new ADDED requirement "Either side of the grace edge is correct" states, for both outcomes, that the incarnation the returned value belongs to has a live holder and is not canceled. The reclaimed branch asserts it (18 ms poll on `firstEnded`, `:817`), the grace-won branch does not: it only waits for `firstEnded` and counts puts, so a replacement incarnation that a queued `fire` or a stale watcher canceled while `ctx2` was still live would pass. `TestTable_ZeroGraceOpenRacesCancel` (`:853`) has the same hole at grace 0 (`else { waitUntil(ended) }`). No branch of either stress test inspects `tab.items`, so "no value is left stored after its lifetime was canceled" is also unpinned.
   → In the grace-won branch, poll `!secondEnded.Load()` for a bounded window while `ctx2` is live and assert `tab.items["a"].value == second`; add the same aliveness check to the `second != first` arm of `TestTable_ZeroGraceOpenRacesCancel`.
   Status: done
   Argument: Applied to both. The grace-won branch of `TestTable_ReclaimRacesFire` now waits past the grace edge and fails if the replacement was disposed while `ctx2` was live, and the `second != first` arm of `TestTable_ZeroGraceOpenRacesCancel` got its own `secondEnded` probe. The stored-value check moved out of the branches: both tests now assert `tab.items["a"].value == second` on every round, so the returned value is the stored incarnation whichever side of the edge won.
3. [judgement] Assertion does not prove the job — `pkg/reclaim/table_test.go:825` — in the reclaimed branch of `TestTable_ReclaimRacesFire`, `secondEnded` can never be true, so "reclaim must not run create" cannot fail: `create` runs only when the key is absent at the first lock, and a lost create can never return `first`, because `fire` deletes that slot permanently before the key can be absent. The put-count check at `:832` is equally unfailable — a distinct pointer means the value was stored, and `MsgPut` is logged before `Open` returns.
   → Count `create` calls in an `atomic.Int32` inside the create func and assert it stayed at 1 on the reclaimed side; replace the put count with a check that can fail, e.g. the stored slot value equals the returned pointer.
   Status: done
   Argument: Applied as written: a `creates` counter incremented inside both create funcs, asserted at 1 on the reclaimed side, and the unfailable put count replaced by the stored-value check described in finding 2.
4. [judgement] Assertion does not prove the job — `pkg/reclaim/table_test.go:228` — raising `TestTable_OpenDuringGraceReclaims` to `graceNoRace` (5 s) removed the race but also removed the test's teeth: the 100 ms window that watches `ended` ends 4.9 s before any armed timer could fire, so a reclaim that failed to invalidate grace would pass. The deterministic substitute (`TestTable_StaleFireAfterReclaimNoops`, `:649`) covers only a queued `fire` carrying a stale generation, not the state left on the slot.
   → After the reclaim, assert under `tab.mu` that `graceTimer == nil` on the mapped slot; that is deterministic and independent of the grace value.
   Status: done
   Argument: Applied as written. The 100 ms watch loop is gone; the test reads `graceTimer` on the mapped slot and fails if the reclaim left it armed, then checks the close flag once. Also cuts 100 ms of wall clock.
5. [judgement] Assertion does not prove the job — `pkg/dbwrappers/reclaim_test.go:148` (and `:269` for MMDB) — with the lease raised to `graceReclaimSafe` (5 s), the 50 ms sleep plus lookup cannot fail; nothing can dispose the handle inside that window. Both `SameHashReclaimKeepsTicker` tests also discard the recorder `useLeases` returns, so they assert no reclaim event at all and the reclaim branch rests on pointer equality alone. The integration-level proof that a reclaimed handle outlives its grace deadline is gone from this package.
   → Use the returned recorder: assert `reclaim_reclaim` for the key and the absence of `reclaim_dispose` for it, and drop the sleep.
   Status: done
   Argument: Applied, and it found more than the finding claimed: with the recorder wired up, neither test was taking the reclaim branch at all - the events were put, bind, bind. Cancelling a holder and calling `Open` straight after usually lands before the holder's watcher has dropped, so it was a plain second bind and pointer equality was trivially true. Both tests now wait for `reclaim_orphan` first, then assert `reclaim_reclaim` and the absence of `reclaim_dispose` for the key, before and after the lookups. Runtime fell to 0.05 s. The trailing `settleFirstTick` sleep stays - it is teardown for the `pkg/dbsource` shutdown gap, see performance finding 3 - but it is no longer load-bearing for any assertion. Added the trap to the usage packet's Gotchas.
6. [judgement] Assertion does not prove the job — `pkg/reclaim/table_test.go:1373` — `TestTable_ResetRacingOpenClosesEveryValue` ends on `closed.Load() == created.Load()`, which is satisfied by one value closed twice plus one never closed, and `waitUntil` returns on the first sample that matches. Nothing checks the test's stated job ("never leaves a created value stored on a dead table"), and the new SHALL "`Close()` SHALL be called at most once per incarnation" is pinned by no test: every other probe is an idempotent `atomic.Bool` (`box.Close` `:32`, `closeProbe.Close` `:950`).
   → Give each value its own Close counter and assert exactly 1 per created value, and assert `len(tab.items) == 0` after the final `Reset`.
   Status: done
   Argument: Applied as written. `counterClose` counts its own closes, every created value is registered in a slice, and the test asserts exactly 1 close per value plus an empty table after the final `Reset`. That is what pins "Close() at most once per incarnation"; the old aggregate was satisfied by one value closed twice and another never closed.
7. [judgement] Assertion does not prove the job — `pkg/reclaim/table_test.go:1065` — the goroutine guard for the new SHALL ("every goroutine the table starts for a key SHALL exit") allows `base+8` against the ~100 goroutines 50 keys start, so a leak of up to 8 passes, and `base` is a process-wide `runtime.NumGoroutine()` that already includes goroutines earlier tests parked forever (e.g. the `context.Background()` watcher in `TestTable_OpenBackgroundDoesNotPanic`, `:434`). On a many-core runner, runtime goroutines that appear during the test consume the same slack, which is the only way this line can flake.
   → Shrink `slack` to a small constant (1–2) now that both goroutines are joined deterministically, or count the table's own goroutines by wrapping `create` and the holder context instead of sampling the process count.
   Status: done
   Argument: Shrunk to 2, with a comment saying what the slack is now for (runtime goroutines around the sample, not a share of the ~100 the keys start). Kept the process count rather than instrumenting `create`: the point of the check is that nothing outlives the key, and a wrapper would only count the goroutines the test already knows about. 25 runs of the test alone and 8 stressed full-suite runs under 12 CPU burners at GOMAXPROCS=2 are green.
