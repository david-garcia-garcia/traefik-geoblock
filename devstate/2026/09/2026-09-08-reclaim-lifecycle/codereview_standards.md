# Standards

1. [hard] Symmetry and consistency — `pkg/dbwrappers/bin.go:95` — this change gives both wrappers the same new sibling shape, `func (w *BIN) startUpdate() error` (`bin.go:208`) and `func (w *MMDB) startUpdate() error` (`mmdb.go:85`), and then handles the identical failure two ways at the two constructors: `newBIN` does `if err := w.startUpdate(); err != nil { w.logger.Error("source updater", "error", err) }` and returns a working BIN, while `newMMDB` does `if err := w.startUpdate(); err != nil { return nil, err }` (`mmdb.go:77`) and aborts construction — for the same `dbsource.Start` error, which is a `Normalize` config failure in both. The divergence in effect predates the change, but the shared `error` return the two call sites disagree about is new here; the sibling `Wake` methods (`bin.go:349`, `mmdb.go:186`) both log, so MMDB alone is fatal in one of its two callers.
   → Pick one contract for the pair and write it in both constructors: either both log-and-continue (BIN's shape, consistent with both `Wake` bodies), or both `return nil, err`; if BIN must stay lenient because of `BINConfig.AllowMissing`, say so in the `startUpdate` doc comment on both types so the asymmetry is the documented rule rather than a leftover.
   Status: open
   Argument: none.
2. [hard] Leave a trail — `pkg/dbwrappers/bin.go:49` — the new mutex field carries the comment `// mu guards every field a hot swap, a sleep, or a wake replaces`, but a hot swap replaces `currentLocalDbCopy` twice and only one of the two writes is guarded: `hotSwap` sets it under `w.mu.Lock()` (`bin.go:251`), while the `createLocalCopy` call it makes first sets `w.currentLocalDbCopy = tmpFile` (`bin.go:175`) with no lock held. The new field's stated invariant is therefore false on the day it is introduced, and it is the contract the next person adding a field or a reader will follow.
   → Either take `w.mu` around the assignment in `createLocalCopy` (it is not called with the lock held), or narrow the field comment to the fields it actually guards (`db`, `path`, `version`, `sourceDbPath`, `updater`).
   Status: open
   Argument: none.
3. [hard] Name for the scope — `pkg/reclaim/table.go:72` — the new `slot` field `err error` holds exactly one thing, the failure `create` returned, kept so every `Open` parked on `s.ready` replays the same terminal failure (`put`, `table.go:222`); `Open` reads it as a bare `err := s.err` (`table.go:200`). On a slot that the package now drives through four value calls (create, Wake, Sleep, Close), the bare stem does not say which call failed or that it is permanent for the incarnation, and the `slot` doc comment (`table.go:69`) lists "the value, what may be done with it, and how many holders need it" without mentioning it, so there is no other anchor.
   → Rename the field to `createErr` and add it to the `slot` doc comment as the create failure this incarnation is stuck with.
   Status: open
   Argument: none.
4. [judgement] Data Clumps — `pkg/reclaim/table.go:152` — `func dispose(key string, value any, logger *slog.Logger)` takes a trio that is really one slot plus the key the slot does not carry, and every ending path re-assembles it by hand: `value, logger := s.value, s.logger` in `drop` (`table.go:301`), the same pair in `expire` (`table.go:346`), and `state, value, logger := s.state, s.value, s.logger` in `Reset` (`table.go:371`). Three destructurings and a three-argument signature for facts that always travel together; the cost is small today but a fourth ending path or a fifth field on the slot pays it again.
   → Store `key` on the `slot` when `Open` registers it (`table.go:177`) and make the ending a slot method, so `drop`, `expire`, and `Reset` call `s.dispose()` instead of unpacking the same three fields.
   Status: open
   Argument: none.
