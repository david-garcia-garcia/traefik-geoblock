# Security

1. [hard] Secrets in logs — `pkg/dbsource/updater.go:120` — the rewritten `tick` logs the raw transport error from `UpdateIfNeeded`, and that error chain is `download failed: %w` around the `*url.Error` returned by `client.Do` in `pkg/dbutils/httpget.go:26`, whose `Error()` renders `Get "<full URL incl. query>": ...`. README documents the source URL as `https://www.ip2location.com/download?token=YOUR_TOKEN&file=...` and `https://ipinfo.io/data/ipinfo_lite.mmdb?token=YOUR_TOKEN`, so any DNS/dial/TLS/timeout failure writes the operator's live download token at Error level. Source is the operator `Source.URL` config field, sink is the process log, and nothing between them redacts: `dbutils.DownloadHint` deliberately omits the URL ("tokens may be in the query") but is only applied on non-200 and unpack failures, not on the transport error. The failing line is pre-existing context rather than an added line, but the diff rewrote `tick` around it and `Wake()` (`pkg/dbwrappers/bin.go:348`, `pkg/dbwrappers/mmdb.go:185`) adds a brand-new trigger: every reclaim of a sleeping wrapper runs an immediate `tick`, so the leak now fires on wrapper wake, not only at process start and on the 24h ticker.
   → In `tick`, log through the same redaction the rest of the download path uses: emit `key` plus the URL host and whether headers/token are set, and pass the error through a scrubber that strips the query (or wrap `HTTPGet`'s `client.Do` failure as `download failed to <host>: <net error>` instead of `%w` on the `*url.Error`).

2. [judgement] New network egress — `pkg/dbwrappers/bin.go:356`, `pkg/dbwrappers/mmdb.go:193` — `Close()` no longer calls `updater.Stop()`; stopping the token-bearing download loop moved into the new `Sleep()`, and the only thing that guarantees Close never runs on a wrapper with a live ticker is the doc comment "always after Sleep". I traced every path in the new `Table` and today the invariant does hold: `expire` is only reached from `drop` after `sleepValue`, and `Reset`'s `slotAwake` branch calls `sleepValue` before `dispose`. But `Close` is exported on an exported type with no state check, so a caller that closes without sleeping leaves an `Updater` goroutine that no one can reach any more (the slot is unmapped and `w.updater` is only reachable via the wrapper) still fetching the operator URL with its auth headers on a 24h ticker and still writing dated files and `update-<key>.lock` into `cfg.Dir` for the life of the process — outbound egress and filesystem writes attributed to a config the operator believes is torn down. Defense-in-depth: no reachable path in this diff, so judgement rather than hard.
   → Make `Close()` self-sufficient: take `w.mu`, swap out `w.updater`, and `Stop()` it before releasing the handle (`Stop` is already idempotent, nil-safe, and joins the loop), so the invariant is enforced by the code rather than by call ordering documented in a comment.
